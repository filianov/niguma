# Архитектура и инфраструктура 15minYoga

Цель — **автономный бизнес одного человека**: построенная один раз воронка
перезапускается на каждый поток, рутину ведут AI-агенты, время автора уходит только
на живые занятия, контент и редкие решения по эскалации.

Подход вдохновлён практикой YC (Garry Tan и др.): сначала делать вручную, автоматизировать
только то, что уже отработано руками; один источник правды; ship MVP сегодня, а не идеальную
платформу через квартал.

---

## 1. Принципы (operating principles)

1. **Сначала — вручную (do things that don't scale).** Первые потоки автор лично пишет каждому лиду, вручную высылает реквизиты и заводит участников. Автоматизируем шаг только после того, как он отработан руками — бот кодирует то, что уже сработало.
2. **Единый источник правды.** Одна база (CRM back-office) — канонический реестр лидов, участников, подписок, платежей. Лендинг, бот, планировщик и e-mail читают/пишут в неё. «Если этого нет в базе — этого не было».
3. **Автоматизируем повторяемое, человек — в точках высокого рычага.** Любая задача, одинаковая в каждом потоке (напоминания, прогрев, анонс старта, подтверждение оплаты) → cron/агент. Время автора — на преподавание, контент и решения, которые агент эскалирует.
4. **MVP на этой неделе.** Лендинг + бот + одна таблица + ручные платежи. Работающий поток с 10 платящими участниками важнее красивой непостроенной LMS.
5. **Слушать пользователей непрерывно.** Бот — ещё и «слуховой аппарат»: каждый вопрос, отказ и возражение логируется и разбирается раз в неделю. Тексты воронки переписываются под реальные формулировки людей.
6. **Минимум данных — минимум ответственности.** Собираем только Telegram id, язык, по желанию e-mail/имя. Никаких медицинских данных. Меньше данных = меньше GDPR-поверхности и доверчивее регистрация.
7. **Автономия с «стоп-краном» и эскалацией.** Агенты ведут 95% happy path сами, но любое денежное решение и любой ответ с низкой уверенностью ставится на паузу и пингуется автору. Система должна провести поток, пока автор на ретрите — и «падать безопасно», а не громко.
8. **Идемпотентность и наблюдаемость.** Каждая задача планировщика безопасна к повторному запуску (без двойных списаний/рассылок) и пишет в `message_log`. Сломалось в 6 утра — читаешь одну таблицу, а не чаты.
9. **Портативность, без вендор-лока.** Открытые форматы и экспортируемые инструменты (Postgres, чистый HTML, SMTP, Telegram Bot API) — бизнес можно переехать за выходные.
10. **Одна воронка, повторяемая.** Бизнес — это одна хорошо настроенная воронка потока, которую система перезапускает по расписанию. Компаундим её, а не плодим продукты.

## 2. Технологический стек

| Слой | Выбор | Почему |
|------|-------|--------|
| **Хостинг лендинга** | **Vercel** (free Hobby) или Cloudflare Pages — статический HTML/CSS/JS | Деплой без сборки, глобальный CDN, бесплатный HTTPS, чистые URL и заголовки безопасности из `vercel.json`. `vercel --prod` — и готово. |
| **Хостинг бота** | **Railway** или **Fly.io** (hobby) — долгоживущий контейнер | aiogram нужен постоянный процесс (long-polling) + воркер для cron. Дешёвый always-on контейнер, managed Postgres рядом, секреты в env. Без serverless cold-starts. |
| **База / CRM** | **PostgreSQL** (Supabase free / Neon / Railway). На MVP — SQLite | Единый источник правды. Supabase даёт бесплатную админку-таблицу — автор правит CRM в браузере без отдельной панели. Легко экспортируется. |
| **Планировщик** | **APScheduler** внутри бота + **GitHub Actions cron** как внешний «сторож» | Напоминания/drip/анонс живут рядом с ботом и базой. Бесплатный GitHub Actions раз в день дёргает health-endpoint — независимый пульс, если контейнер упал. |
| **E-mail / ESP** | **Resend** (free ~3k/мес) с домена; входящие — Google MX | Telegram — основной канал, e-mail — резерв/чеки. Чистый API, простая настройка SPF/DKIM/DMARC, хорошая доставляемость транзакционных писем. |
| **Аналитика** | **Plausible** (cookieless) на лендинге + события в БД | GDPR-friendly без баннера согласия. Правда воронки (лид→оплата) живёт в БД. |
| **Платежи** | Ручная выдача реквизитов через бота → апгрейд до **Paddle/Stripe + PayPal** | Старт максимально простой; MoR-провайдер снимает НДС. См. [PAYMENTS.md](PAYMENTS.md). |
| **Трансляции** | **Zoom** (Pro) + опционально видеочат в приватном Telegram-канале | Низкий порог для йога-аудитории, автозапись. Бот выдаёт ссылку только активным участникам ко времени занятия. |
| **Хранилище записей** | **Cloudflare Stream** (подписанные ссылки) или непубличный YouTube + приватный Telegram-канал | Записи — актив удержания, нужен контроль доступа. Бот — привратник: подписка кончилась → доступ закрылся. |
| **AI / LLM** | **Anthropic Claude** — Haiku (`claude-haiku-4-5`) для массового саппорта/FAQ, Sonnet (`claude-sonnet-5`) для тонких продаж/эскалаций | Haiku дёшев и быстр для интент-детекта и мультиязычных ответов; сложные диалоги → Sonnet. Кэш системного промпта + базы знаний снижает цену. Порог уверенности → эскалация автору вместо галлюцинаций. |

## 3. Модель данных (минимальная, GDPR-friendly)

Реализована в [`bot/db.py`](../bot/db.py). Сущности:

- **lead** — `telegram_id` (uniq), username, first_name, language, source/utm (из start-параметра), goal, experience, email (опц.), `consent_marketing` + `consent_ts`, lead_score, status (`new|nurturing|trial|converted|lost`), drip_step/drip_due, created_at, last_activity_at.
- **member** — lead_id, telegram_id, display_name, language, timezone, email (опц.), status (`active|paused|churned`), seeds, streak/longest_streak, last_practice_date, joined_at. **Намеренно без медицинских данных.**
- **subscription** — member_id, cohort/поток, plan, status (`pending|active|expired|cancelled`), start/end, price, currency, payment_method, renewed_from.
- **payment** — subscription_id, member_id, telegram_id, amount, currency, method (`paypal|stripe|iban|monobank|wise|stars`), status (`pending|confirmed|refunded`), proof_ref, confirmed_by, timestamps.
- **practice_log** — member_id, session (`daily|weekly`), practice_date, source (`live|recording|self`). Сигнал удержания → напоминания, churn-save, геймификация.
- **seed_log** — member_id, event_type, points, balance_after, note, related_ref. Леджер геймификации.
- **message_log** — recipient (lead/member), channel, direction (in/out), automation (`drip_day2`, `reminder_t1h`, `support`, `broadcast`…), intent, llm_confidence, escalated, body. Единый аудит каждого касания.

## 4. Воронка и автоматизации

Подробно — в [FUNNEL.md](FUNNEL.md). Кратко, автоматизации:

- **Напоминания о занятиях** (cron T-60 / T-10) — только активным участникам, идемпотентно.
- **Drip-прогрев** (день 0/2/3/4) — персонализирован по цели и языку, на паузе при конверсии/отписке.
- **Re-engagement / churn-save** (ежедневно) — N пропусков → персональное сообщение, молчунов эскалируем автору.
- **Анонс «стартует поток»** (понедельник) — тёплым лидам + спящим, с учётом лимитов Telegram.
- **Контент-дрип** (ежедневно) — короткий совет/клип по локали в каналы.
- **Лид-скоринг** (по событиям + ночью) — приоритизация для рассылок и ручного касания.
- **Жизненный цикл оплаты** (по событию) — чек → pending → пинг автору → подтверждение → активация + доступ + чек.
- **Истечение/продление** (ежедневно) — оффер продления до конца потока; по истечении — отзыв доступа.
- **FAQ/саппорт** (реалтайм-агент) — Haiku отвечает из базы знаний; ниже порога уверенности → лог + эскалация.

## 5. Риски и митигации

| Риск | Митигация |
|------|-----------|
| **Зависимость от Telegram** (бан/лимиты/блокировки) | Хранить e-mail/согласие как резервный список, держать тёплым канал лендинг+Resend, уважать rate limits, держать данные экспортируемыми. |
| **Платежи / санкции / трансгран** | Несколько методов по регионам (Wise/Revolut/SEPA/Stars), деньги двигает только человек (автор подтверждает), чистый учёт, не строить обход санкций. Карты РФ не обслуживаются. |
| **Bus-factor автора** | Агенты ведут happy path сами (идемпотентно, fail-safe «пауза, не двойное действие»), записи закрывают пропуски, runbooks/доступы задокументированы, БД — единый источник. |
| **Доставляемость e-mail** | SPF/DKIM/DMARC на домене, репутабельный ESP (Resend), только транзакционные письма, мониторинг bounce/complaint. |
| **GDPR / приватность** | Минимум данных, явное согласие + таймстемп, без спец-категорий (здоровье), cookieless-аналитика, срок хранения логов, команда `/delete` (экспорт/удаление по `telegram_id`). |
| **IP записей** | Доступ к записям только активной подписке (подписанные/истекающие ссылки), автоотзыв при истечении, водяной знак/приватный канал, условия лицензии в оферте. |
| **Free-tier / вендор-лок / SPOF** | Внешний GitHub Actions heartbeat, открытые форматы (Postgres/HTML/SMTP) для переезда за выходные, регулярные бэкапы/экспорты БД. |
| **Ошибки/галлюцинации AI на деньгах и здоровье** | Порог уверенности → эскалация; реквизиты берутся из конфига, не генерируются; запрет медсоветов в системном промпте; полный аудит ответов в `message_log`. |

## 6. Как агенты «закругляют» базу

Идея автора — чтобы бот «зацикливал и закруглял базу» и вёл клиентов по последовательности
воронки. Реализация:

1. Любой контакт (лендинг-форма, /start, реферал) попадает в `lead` с источником.
2. Квалификатор бота фиксирует цель и опыт, ставит первый шаг drip.
3. Планировщик ведёт лида по drip-цепочке, агент отвечает на любые реплики в треде и поднимает lead_score.
4. На старте потока — сегментированный анонс тёплым лидам и спящим участникам.
5. Оплата → активация → онбординг → удержание (напоминания + геймификация) → продление/реферал.
6. Реферал и продление возвращают цикл к шагу 1 — воронка замыкается и перезапускается сама.
